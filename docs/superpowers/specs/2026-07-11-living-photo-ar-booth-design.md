# 리빙포토 AR 포토부스 — 설계서

- **작성일**: 2026-07-11
- **상태**: 설계 승인(섹션 A) · 뷰어부터 프로토타입 착수
- **성격**: 곧 있을 교회 행사용 **일회성**(수십~수백 명), 가볍고 빠르게

## 1. 개요

교회 행사 **셀프 사진관**. 참석자가 촬영하면 사진이 아니라 **촬영 전후의 짧은 영상**을 캡처하고,
미리 인쇄해둔 **QR 카드**에 그 영상을 연결한다. 나중에 QR을 스캔하면, 카드에 카메라를 비출 때
**공통 3D 액자 안에서 자기 영상이 재생**되는 "살아움직이는 사진(리빙포토)" 기념품.

## 2. 사용자 시나리오

**참석자(보는 쪽)**
1. 받은 QR 카드를 폰 카메라로 스캔 → 뷰어 사이트 열림 (`/v/<token>`)
2. 폰을 카드에 비춤 → 카드(공통 디자인) 인식 → **3D 액자 안에서 내 영상 재생** 🙏

**부스 운영(찍는 쪽)**
1. 참석자가 웹 부스 앱 앞에서 촬영(셀프)
2. 촬영 전후 영상이 자동 녹화됨
3. 건네줄 QR 카드를 스캔 → 방금 영상이 그 QR(token)에 연결·업로드

## 3. 전체 구조 (4개 서브시스템)

```
[① 웹 부스 앱]  셀프 촬영 → 전후 자동 녹화(mp4) → QR 스캔 연결 → 업로드
        │
        ├─ 업로드 ─→ [② 저장/매핑]  Supabase Storage(clips 버킷) + Table clips
        │
[③ QR 대량생성]  고유 token 담은 QR 여러 장 미리 발급 (인쇄용)
        │
[④ 뷰어]  QR 스캔 → /v/<token> → 매핑 조회 → video_url → MindAR 3D 액자 재생
```

각 조각은 **공통 규약(4장)** 만 지키면 독립적으로 만들고 테스트할 수 있다.

## 4. 공통 규약 (모든 조각이 지키는 약속)

- **토큰(token)**: QR마다 고유한 짧은 랜덤 코드(예: 6자, 추측/열거 방지). QR 내용 = `https://<사이트>/v/<token>`.
- **저장**: Supabase Storage `clips` 버킷에 `<token>.mp4`. 매핑은 `clips` 테이블 한 줄.
- **영상 포맷**: **MP4 / H.264 고정.** ⚠️ 아이폰 Safari는 webm 재생 불가 → AR 영상 텍스처가 iOS에서 나오려면 필수. (부스 단계에서 "녹화 → mp4 보장" 처리)
- **마커**: 카드 **공통 디자인 1개** → `target.mind` 1개로 모든 카드 커버. QR은 데이터(token)만 담당.
- **3D 액자**: 공통 프레임 1개, 그 안 스크린 면에 영상 텍스처. three.js로 직접 모델링(외부 3D 파일 불필요).

## 5. 기술 스택

| 구분 | 선택 |
|---|---|
| 호스팅/배포 | Vercel (정적 + 서버리스 함수) |
| 저장/매핑 | Supabase (Storage + Postgres 테이블) |
| AR/렌더 | MindAR(image tracking) + three.js (CDN) |
| QR 생성 | segno(파이썬) 등으로 배치 발급 |

### 데이터 모델 (Supabase)

- Storage 버킷 `clips` (public read).
- 테이블 `clips`:
  - `token text primary key`
  - `video_url text`
  - `created_at timestamptz default now()`
  - (선택) `status text` — 발급됨/연결됨

## 6. 서브시스템 상세

### ④ 뷰어 (가장 먼저)
- 라우트 `/v/<token>` → 테이블에서 token 조회 → `video_url` 확보.
- MindAR로 카드(공통 마커) 인식 → anchor에 3D 액자 + `<video>` VideoTexture 재생.
- iOS 자동재생 위해 `muted playsinline` (소리는 탭 시 on).
- 미연결 token/로드 실패 시 안내.

### ③ QR 대량생성
- N개의 token 생성 → 각 `https://<사이트>/v/<token>` QR PNG 배치 출력(인쇄용 시트).

### ② 저장/매핑
- 업로드용 경로: 부스앱 → Supabase(정책상 익명 업로드 허용 or 부스 전용 키).
- 업로드 완료 시 `clips`에 (token, video_url) upsert.

### ① 웹 부스 앱 (가장 나중)
- getUserMedia로 카메라 미리보기 + MediaRecorder 롤링 버퍼(셔터 전후 N초).
- QR 스캔(BarcodeDetector 등)으로 token 획득 → 영상 업로드 + 매핑.
- **mp4 보장**: iOS 재생 위해 H.264 mp4 필요. 녹화 포맷이 webm이면 트랜스코딩(서버리스 ffmpeg) 필요 — 부스 단계에서 확정.

## 7. 빌드 순서 (하나씩, 데모 가능하게)

1. **④ 뷰어** — 테스트 영상 1개로 "저장→QR→재생" 코어 루프부터 (지금 착수)
2. **③ QR 생성 + ② 저장** — token 체계 + 업로드
3. **① 부스 앱** — 자동 녹화 + 연결 (제일 손 많이 감)

## 8. 열린 항목 / 리스크

- **카드 아트 디자인**: 실제 공통 카드 그래픽은 별도 디자인 필요. 프로토타입은 임시 마커로 진행 후 교체.
- **mp4 트랜스코딩**: 부스 녹화가 webm이면 iOS용 mp4 변환 경로 필요(서버리스/기기 선택). 부스 단계에서 결정.
- **iOS 영상 자동재생/AR 텍스처**: `muted playsinline` + 사용자 제스처 정책 확인.
- **개인정보**: 영상은 개인 얼굴. 행사 후 만료/삭제 정책, 링크 추측 방지(랜덤 token) 고려.
- **동시 업로드**: 일회성·수백 명 → Supabase 무료 tier로 충분하나 용량/대역 모니터링.

## 9. 범위 밖 (이번 아님)

- 로그인/회원, 결제.
- 영상 편집/필터 고급 기능.
- 여러 행사 관리 대시보드(재사용 시스템은 후속).
