# AR 리빙포토 뷰어 — 어드민 연동 가이드

성락네컷 AR 뷰어(`webar-goods.vercel.app`)에 실제 영상을 배정하는 방법.
뷰어는 아래 규칙만 지키면 수정 없이 그대로 동작한다.

## 연동 인터페이스 (전부)

```
어드민 → Vercel Blob에  clips/<token>.mp4  저장
카드 QR →  https://webar-goods.vercel.app/fx/<token>
```

이 두 가지가 전부다. 뷰어는 `/fx/<token>` 접속 시 `/api/clip?t=<token>`으로
Blob 목록을 조회해 첫 번째 영상을 재생한다.

## 토큰 규칙 (필수)

- **소문자 영문 a-z, 숫자 0-9, 하이픈(-)만, 3~24자**  — 예: `sr0001` (O), `SR_0001` (X)
- URL 경로와 Blob 파일명 양쪽에서 같은 정규식(`/^[a-z0-9-]{3,24}$/`)으로 검증됨
- 대문자로 접속해도 뷰어가 소문자로 변환하지만, **Blob 파일명은 반드시 소문자**로 저장할 것

## 미디어 규칙

- **영상만 지원** (mp4 권장, mov 가능). 정지 이미지(jpg/png)는 뷰어가 재생하지 못함
- 세로/가로 아무 비율이나 가능 — 뷰어가 영상 메타데이터로 높이를 자동 계산
- 권장 스펙: H.264 mp4, 세로 720×1080 내외, 수 초~수십 초 루프, **15MB 이하**(현장 LTE 고려)
- 무음/유음 모두 가능 — 뷰어가 시작 탭 제스처로 소리를 켜므로 오디오 트랙이 있으면 자동 재생됨
- 같은 토큰에 여러 개 저장 가능: `clips/<token>.<slot>.mp4` — 뷰어는 첫 영상 하나만 사용
- **재배정(교체)**: 같은 파일명으로 덮어쓰면 즉시 반영됨 (`/api/clip`은 no-store 캐시)

## 배정 전 카드의 동작

영상이 아직 없는 토큰으로 접속하면 뷰어가 "영상 준비 중…"을 표시하며
2.5초 간격으로 최대 100초 재시도한다. 그 사이 어드민이 업로드하면 자동으로 이어진다.

> 구 부스 플로우의 "첫 스캔 바인딩"(빈 카드가 부스의 '현재 영상'을 자동으로 물어가는 로직)은
> 어드민 명시 배정과 충돌하므로 **제거됨** (2026-07). 배정은 어드민에서만 일어난다.

## 카드 인쇄 시 주의 (AR 마커)

- AR 마커는 **카드 이미지 자체**로 학습돼 있다 (`8w/image-targets/qrcard.*`, demo01 카드 기준)
- 카드마다 QR 내용이 달라지면 마커 그림이 달라져 **인식률이 떨어질 수 있음**
  → 실물 카드 2~3장(서로 다른 토큰)으로 인식 테스트 권장
- 카드 디자인(테두리·타이틀·로고)은 바꾸지 말 것 — 바꾸면 마커 재학습 필요

## 뷰어 URL 파라미터 (운영/디버그)

| 파라미터 | 용도 |
|---|---|
| `?guide=0` | 시작 가이드 끄기 (기본: 접속할 때마다 표시, 탭으로 단계 넘김) |
| `?gmin=8000` | 가이드 최소 표시 ms (기본 8000 = 애니 한 루프) |
| `?preview=1` | 데스크톱 미리보기 (카메라 없이 씬 확인, 가이드 항상 표시) |
| `?intro=0` | 등장 연출 생략 |
| `?scale=1.2` 등 | 크기·연출 미세 튜닝 (fx2.html 옵션 블록 참고) |

## 환경변수

- `BLOB_READ_WRITE_TOKEN` — Vercel Blob 접근 토큰 (어드민이 같은 스토어에 쓰면 됨)
